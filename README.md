# ふるさと納税マネージャー

スマホ向けPWAとして使える、ふるさと納税の上限推定・寄附・返礼品配送管理アプリです。

## 主な機能
- ホームは簡潔な推定上限・寄附済み・残り目安
- 「上限額の計算詳細」で月別給与、賞与、社会保険、iDeCo、地震保険、その他控除、臨時支給、計算過程を確認
- 今年の実績と、10〜12月の予測を明示
- 前年給与・賞与は予測参考として別管理
- 自動取得値と手動修正値を分離
- 寄附一覧・配送予定・確認待ちを管理
- 注文IDやメール情報による重複検出
- 給与CSV・メールJSONのローカル取り込みでOAuth接続前のテストが可能
- Google Drive / Yahoo!メールは公式OAuthを利用するバックエンドを接続する設計。パスワードは保存しない
- JSONバックアップ／復元

## 給与CSVテスト形式
1行目に `month,gross`、2行目以降に `1,470000` のように記載します。日本語見出し `月,給与` や `月,支給額` も認識します。

## メールJSONテスト形式
```json
[
  {"messageId":"abc-001","subject":"ふるさと納税 寄附受付 注文番号 R-12345","body":"寄附金額 30,000円 発送予定 9月27日","date":"2026-09-17"}
]
```

## 税計算について
2026年の給与所得控除・基礎控除等を前提にした「年途中の推定」です。最終的な上限は年末の所得・控除・住民税額等で確定するため、アプリは「推定」と「安全目安」を分けて表示します。

## 実運用への接続

`server.js` にOAuth開始エンドポイントを用意しています。Googleは `GOOGLE_CLIENT_ID` / `GOOGLE_REDIRECT_URI`、Yahoo!は `YAHOO_CLIENT_ID` / `YAHOO_REDIRECT_URI` をサーバー環境変数に設定します。クライアントシークレットやOAuthトークンを静的HTMLへ埋め込まない構成です。


Google Drive / Yahoo!メールのOAuthは、各サービス側でアプリ登録・リダイレクトURL等を設定したバックエンドを接続して利用します。認証情報をこの静的PWAに埋め込まない設計です。


## 今回取り込んだサンプル
- `1219856-Bonus-202607.pdf`: 2026年7月賞与の支給合計 5,550,000円を実績として登録。賞与からの社会保険料は雇用保険・健康保険・介護保険・子ども・子育て支援金・年金保険の記載額を合計した 388,387円を別管理。持株会 1,333,000円と所得税 1,159,401円は社会保険料に含めない。
- `1219856-Assets-202608.pdf`: 資産形成・DC等の資料として記録するが、給与や所得控除へは自動反映しない。iDeCo等への該当は資料だけでは確定しないため確認待ち。
- 既存のデモ状態が残っている場合、旧デモ賞与 600,000円だけを自動的に今回の実績へ移行し、手動編集済みデータは上書きしない。


## Google Drive（PWA）接続

設定画面の「Google Driveを接続」から、Google Cloudで作成した**Webアプリ用 OAuth クライアントID**を入力します。クライアントシークレットは入力しません。Google公式のJavaScript向けDriveクイックスタートでは、Google Drive APIを有効化し、Google Auth PlatformでWeb applicationのClient IDを作成し、アプリのAuthorized JavaScript originsを登録する流れです。

必要な権限はこのアプリでは `https://www.googleapis.com/auth/drive.readonly` の読み取り専用です。認証後、Drive内のPDFからファイル名に「給与・給料・賞与・ボーナス・源泉徴収票」等を含む候補を検索し、PDF本文を解析して2026年の給与／賞与データを取り込みます。判定できないものは確認待ちにします。

Googleのアクセス用トークンはメモリ上だけで扱い、アプリのJSONデータやバックアップには保存しません。Google Drive APIはOAuth 2.0を使用します。

## 2026年の給与・賞与予測ルール
- 1〜9月は対象年の実績を使用。
- 10〜12月の月給は、前年の給与を使わず、対象年4〜9月の実績平均を各月に適用。
- 10〜12月の給与分社会保険料も、前年を使わず、対象年4〜9月の実績平均を各月に適用。
- 賞与だけは前年同シーズンを参考にする。対象年に夏賞与が未支給なら前年夏賞与、冬賞与が未支給なら前年冬賞与を予測値に使用。対象年にそのシーズンの賞与が支給済みなら前年分は重ねない。
- したがって、給与・給与分社会保険料の予測に前年の昇給前データを混ぜない。


### 給与データ未取得時
給与明細をまだ取り込んでいない状態では、サンプル給与額を実績として表示しません。Google Driveから取得した実データ、または手動入力したデータだけを給与実績として使用します。

## 給与明細PDF解析の重要な実装方針（2026-09-20）
- 給与収入は「支給合計」を無条件に採用せず、明細に明記された「課税対象額 / Taxable Amount」を最優先します。
- PDF.jsの文字列順だけでは給与欄と金額欄が入れ替わることがあるため、給与・賞与の主要金額はラベルと金額の近接関係に加え、表構造・単位・算術整合性を検証します。PDF.jsで座標が取得できる場合はレイアウト情報も利用します。
- 「課税対象額」が見つからず、かつ非課税額も明示されていない場合は給与を0円に補完せず、確認待ちとして扱います。
- 同じ給与明細を再取り込みした場合は、過去の自動取得値を最新解析結果で置換します。手動入力値は保持します。これにより旧解析ロジックの誤値が残り続ける問題を防ぎます。
- Google Drive検索はファイル名に年月が含まれない給与明細にも対応し、PDF本文の年月で対象年/前年を判定します。対象外年は保存しません。
- 賞与は実際の賞与明細を優先し、健康保険・介護保険・厚生年金・雇用保険・子ども・子育て支援金を個別に保持します。標準賞与額の健保・厚年も別々に検証します。
- 2026-09-20時点で、6月給与（課税対象804,000円）、8月給与（課税対象784,190円）、7月賞与（5,550,000円、社会保険料388,387円）の再現テストを実施しています。

## 給与明細PDFの読み取り（2026-09-20）
- Google Drive検索はファイル名に `1219856` を含むPDFに限定します。
- 対象年と前年以外の年月はPDFをダウンロードせず、解析もしません。
- 給与・賞与・源泉徴収票は通常のPDFテキスト解析を優先し、文字レイヤーが空、または主要項目の構造検証に失敗した場合にOCRへフォールバックします。
- OCRは補助経路です。PSM 11/6 の複数結果を統合し、ラベルと数値が片方ずつ認識されるケースにも対応します。主要値が算術的に一意に確定できない場合は確認待ちにします。
- 取込履歴にはOCR使用状況と解析結果を保存します。

- 給与明細の課税対象額は、明細下部の「支給合計 − 非課税額」を再構成できる場合は直接の「課税対象額」取得に依存しません。
